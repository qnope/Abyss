# Data Layer

The data layer is the persistence layer of the Abyss project. It lives in `lib/data/` and uses [Hive](https://pub.dev/packages/hive_flutter) for local storage.

## Overview

This layer contains two classes:

- `GameRepository` (`lib/data/game_repository.dart`) -- initializes the database, saves games, loads them and deletes them.
- `LanguageSettings` (`lib/data/language_settings.dart`) -- the game language picked by the player (see [Language settings](#language-settings)).

## GameRepository API

| Method | Return type | Description |
|---|---|---|
| `initialize()` | `Future<void>` | Static. Initializes Hive, registers all adapters, and opens the `games` box. Must be called once at app startup. |
| `save(Game game)` | `Future<void>` | Persists a game. Updates in place if already stored, otherwise adds a new entry. |
| `loadAll()` | `List<Game>` | Returns all saved games from the box. |
| `delete(int index)` | `Future<void>` | Deletes a saved game by its index in the box. |

## Hive Adapter Registration

Hive requires a registered adapter for every type it persists. `GameRepository.initialize()` registers adapters for all domain models in dependency order (leaf types first, composite types last):

1. **Enums** -- `BuildingType`, `ResourceType`, `TechBranch`, `UnitType`, `TerrainType`, `CellContentType`, `MonsterDifficulty`, `HistoryEntryCategory`, `CombatSide`, `GameStatus`
2. **Value objects** -- `Building`, `Resource`, `TechBranchState`, `Unit`, `MonsterLair`, `MapCell`, `GridPosition`, `ExplorationOrder`, `Combatant`, `FightTurnSummary`, `FightResult`, `TurnResourceChange`
3. **Transition types** -- `TransitionBaseType`, `TransitionBase`, `ReinforcementOrder`
4. **History entries** -- `BuildingEntry`, `ResearchEntry`, `RecruitEntry`, `ExploreEntry`, `CollectEntry`, `CombatEntry`, `CaptureEntry`, `DescentEntry`, `ReinforcementEntry`, `TurnEndEntry`
5. **Aggregates** -- `Player` (holds `List<HistoryEntry>`), `GameMap`
6. **Root** -- `Game`

`MonsterLair` is registered before `MapCell` because cells embed an
optional `lair` reference. Fight outcomes (lair `collectedBy`, updated
unit stocks, looted resources) persist through the existing `Game`
serialization -- the fight module itself stores no extra state.

History entries are sealed `HistoryEntry` subclasses, each with its
own `@HiveType` / typeId. `CombatEntry` embeds a full `FightResult`,
which is why the fight value objects (`Combatant`, `FightTurnSummary`,
`FightResult`) are registered even though the fight module itself
still has no dedicated persistence. `TurnEndEntry` carries a list of
`TurnResourceChange` summarising the production delta of the turn.

These adapters are generated by `hive_generator` from `@HiveType` annotations on the domain classes.

## Error Handling

If the `games` box fails to open (e.g., schema migration conflict), `initialize()` deletes the corrupted box from disk and reopens it. This means saved data can be lost on breaking schema changes.

## Usage

```dart
// At app startup
await GameRepository.initialize();

// Then use an instance for CRUD operations
final repo = GameRepository();
await repo.save(game);
final allGames = repo.loadAll();
await repo.delete(0);
```

## Storage

All games are stored in a single Hive box named `games`, typed as `Box<Game>`. The box is accessed via the private `_box` getter.

## Language settings

`LanguageSettings` keeps the player's `LanguageChoice` (`lib/domain/settings/language_choice.dart`: `automatic`, `french`, `english`, `spanish`) in a `Box<String>` named `settings`, under the key `language`. The stored value is the choice's `code` (`fr`, `en`, `es`); `automatic` is never stored, choosing it deletes the key. An unknown code reads as `automatic`.

| Member | Description |
|---|---|
| `static open()` | `Future<LanguageSettings>`. Opens the `settings` box (wiping it and reopening it empty if it cannot be opened) and reads the saved choice. Call it after `GameRepository.initialize()`, which initializes Hive. |
| `LanguageSettings(Box<String>)` | Builds the settings from an already opened box. |
| `choice` / `value` | The current `LanguageChoice`. |
| `choose(LanguageChoice)` | Switches and saves; notifies listeners only when the choice really changes. |

It is a `ChangeNotifier` and a `ValueListenable<LanguageChoice>`, so the app switches language as soon as it changes.
